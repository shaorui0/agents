c0002 deterministic-gates

What changed

  • hooks/k8s_gate.sh (+ k8s_gate.py, config/env_map.yaml): Gate 3 as runnable code. Alias to tier (dev / staging / prod), a hard-block table that applies on every tier, mutating-verb detection on the first non-flag token (so kprod -n y scale ... is caught), # INTENT: reminder, --dry-run allowed, compound commands and bash -c unwrapped.
  • hooks/audit_pre.sh, hooks/audit_log.sh, hooks/audit.py: JSONL audit under records/audit/ (path from AGENTS_AUDIT_DIR), pre and post paired by op_id, reasoning: null when INTENT is missing, Gate 4 reminder after a mutation.
  • .claude/settings.example.json: Gate 2 table and the hook wiring.
  • tests/: 37 tests, no cluster, no network.

Why

The method says safety lives in deterministic code. Until a reader can run the code and try to break it, that is a claim. The point of Gate 3 is the property “no amount of hallucination gets past an exit 2”.

Design decisions

  • Fail-closed on three axes. Unknown alias is prod. Missing config exits 2. Non-JSON stdin exits 2. An unparseable command that names an infra tool is treated as a prod mutation.
  • Verb by position, not by substring. A deny-list regex over the whole string misses kprod -n y scale and false-positives on get pods -l app=create. Tokenising and finding the first non-flag token fixes both.
  • Hard blocks beat dry-run and tier. kdev delete ns foo --dry-run=client still exits 2.
  • Gate never blocks the audit. audit hooks always exit 0; a blocked prod command is still recorded as phase=pre with action: block.

Result

echo '{"tool_input":{"command":"kprod scale deploy x --replicas=1 -n y"}}' | bash hooks/k8s_gate.sh exits 2 and prints the command. 37 tests green. Unknown alias, hard blocks, INTENT reminder, dry-run, compound commands all covered.

Known limit

A verb deny-list is fail-open for verbs it has not seen. The set is wide (includes set, replace, edit, annotate, label), but the second line is Gate 2 plus the audit trail. Scripts that call kubectl internally are invisible to Gate 3.
